# 프로젝트 진행 보고서: 토큰화 주식의 가격 차이를 실제 거래로 확인하기

> 가격을 비교하는 도구를 만들고, SPCX를 직접 사고 옮겨 팔았다. 이후 같은 수량의 매도 견적을 10회 비교해, 참고 가격과 실제 거래 전 견적의 차이를 확인했다.

- 팀: **M3M3** — 신영환, 김다헌, 장윤선, 최준우, 이주호(조장)
- 보고서·아티클·최종 제출 담당: 이주호
- 프로젝트 기간: 2026년 9월 6~14일 / **보고 기준: 9월 11일, 마지막 견적 실험 종료까지**
- 공통 주제: **토큰화 주식은 어떻게 증권계좌와 연결되는가 — 전환 권한과 상환 구조가 만드는 시장의 차이**

## 1. 무엇을 확인하려 했나

Solana에서 거래되는 토큰화 주식을 싸게 사서 Backpack으로 옮긴 뒤 비싸게 팔 수 있는지 확인하는 프로젝트다. 블록체인에서 토큰을 교환하는 거래소를 **DEX**, 브로커에게 원하는 수량의 가격을 요청하는 방식을 **RFQ**라고 한다.

처음에는 가격 차이를 찾는 데 집중했지만, 실험 중에는 다른 질문도 생겼다. **자산을 옮길 수 있어도, 옮기기 전에 팔 가격을 확인할 수 있는가?** 프로젝트는 이 조건을 직접 검증하고, 아티클은 여기서 발견한 질문을 다른 전환 구조와 사용자·기관의 차이로 확장한다.

초기 API 조회에서 Solana 입출금이 지원되는 Backpack 발행 주식 토큰 16종을 확인했다. 주요 가격 비교 대상은 **SPCX·MU·SNDK·SKHY**이며 MSTR·MRNA도 참고 관측했다. 주식 토큰의 실제 이동·거래 실험은 **SPCX에 한정**했다. 같은 이름이라도 발행사와 토큰 고유 주소가 다르면 다른 자산이므로, Backpack 입금 대상 주소와 일치하는 토큰만 사용했다.

## 2. 어떤 도구를 만들었나

기본 계산은 **예상 순수익 = 매도 대금 − 매수 대금 − 추가 비용**이다. 이미 교환 견적에 포함된 수수료와 가격 변화 효과는 다시 빼지 않는다. Backpack 출금 수수료는 받을 토큰 수량에서 차감하며, Backpack으로 입금하는 방향에는 적용하지 않는다.

| 기능 | 구현한 내용 |
| --- | --- |
| 대상·시간대 확인 | 지원 토큰 주소, 입출금 상태, 최소 수량, 미국 거래 시간대 조회 |
| 가격 차이 수집 | 두 시장의 양방향 견적과 비용 반영 예상 수익 기록. 1주·10주 비교 지원 |
| DEX 경로 비교 | Jupiter V1·V2 통합 견적과 Raydium CLMM·Meteora DLMM 제한 견적 비교 |
| 실제 RFQ 연결 | DEX 수령 예정 수량의 Backpack 매도 견적 요청·취소. 실패하면 참고 가격으로 대체하지 않음 |
| 실행·증빙 | 소액 매수·전송·입금·매도와 실제 수령량·체결가·시간 기록 |
| 과거 가격 실험 | 4종의 과거 가격으로 비용·지연 가정을 바꿔 계산하는 백테스트 작성 |

DEX를 제한해도 여러 풀이나 중간 토큰을 거칠 수 있으므로 실제 경로도 저장한다. 개별 DEX 견적을 비교한 것과 해당 DEX에서 실제 거래한 것은 구분한다.

모니터에는 미국 시장 최근가를 쓰는 **기대 모델**과 최근가에 ±15 bps를 적용하는 **보수 모델**을 두었다. 1 bps는 0.01%다. 플래그 기준은 비용 반영 10 bps, RFQ 참고 모델에는 여유 5 bps를 더한 15 bps다. **두 모델과 여유분은 설정값이며 실제 수신 RFQ나 수익 보장이 아니다.** 모니터와 별도로 실제 RFQ를 비교하는 명령을 만들었다. 사용법은 [README](../README.md)에 정리했다.

## 3. 어떤 순서로 실행했나

| 시기 | 수행한 일 | 확인한 내용 |
| --- | --- | --- |
| **9/6~7** | 자산 주소·입출금 조건 확인, 가격 수집 시작 | 시장과 토큰을 연결할 수 있는지 검토 |
| **9/8** | 실험 자금 준비, USDC 입출금, 소수점 RFQ 측정 | 입금 반영 84초, 출금 도착 7초를 각각 1회 관측 |
| **9/9** | SPCX 약 0.02주 왕복, 별도 RFQ 매수·매도 8건, 백테스트 작성 | 토큰 이동과 실제 체결 확인. 견적과 정산가가 다름을 발견 |
| **9/11** | V2·개별 DEX 비교, 2 USDC 경로 실행, 실제 매도 견적 10회 비교 | 새 API 실행 성공. 참고 모델과 실제 RFQ의 차이를 수치로 확인 |

### 먼저, 토큰을 사고 옮겨 파는 경로를 확인했다

9월 9일에는 Solana에서 SPCX 약 0.02주를 매수해 Backpack에 입금했다. 0.01주는 RFQ로 팔고, 0.01주는 다시 출금해 수수료를 뺀 0.006주를 Solana에서 팔았다. **입금은 온체인 확인 후 약 100초**, **출금은 요청 후 약 11초**가 걸렸다.

당시 출금 수수료 **0.004주**는 0.01주의 **40%**였다. 이동이 가능하고 빨라도 소액 왕복에서는 고정 비용이 크게 작용했다. 별도 RFQ 체결 8건에서는 모두 견적보다 유리하게 정산됐지만, 이를 앞으로의 모든 거래에 적용하지 않는다. [기존 실행 기록](../data/exec.jsonl), [RFQ 체결 기록](../data/rfq.fills.jsonl)

### 새 V2 경로도 2 USDC로 실행했다

9월 11일 정규장에는 **Jupiter V2 매수 → Backpack 입금 → RFQ 매도**를 실행했다. V2가 선택한 매수 경로는 GoonFi V2였다.

| 항목 | 실제 결과 |
| --- | ---: |
| 매수 대금 / 수령 SPCX | **2 USDC / 0.013595주** |
| 전송 확인 후 입금 반영 관측 | **약 93초** |
| Backpack 매도 수량 / 대금 | **0.01359주 / 2.0009916 USDC** |
| 매도 견적 / 실제 정산가 | 주당 **147.01 / 147.24 USDC** |
| 네트워크 비용 / 신규 잔여 SPCX | **0.000010209 SOL / 0.000005주** |

USDC 차액은 +0.0009916이지만, SOL 비용 환산과 잔여 토큰 평가 전이므로 순이익이라고 판정하지 않았다. 이 거래는 가격 차이 신호를 따라 진입한 거래가 아니라 **경로의 실행 가능성을 확인한 소액 실험**이다. 새 V2로 반대 방향까지 실행하거나 모든 DEX·종목을 거래한 것은 아니다. [상세 실행 기록](../data/spcx-v2-2usdc-20260911.json)

### 마지막으로, 같은 수량의 실제 매도 견적을 반복 비교했다

앞선 약 1주 매도 RFQ는 잔고 부족으로 거절됐다. 2 USDC 실험 후에도 남은 SPCX가 0.000093주라, 정규장 최소 0.01주 견적을 받을 수 없었다. 그래서 승인된 예산 안에서 **0.01주를 1.476 USDC에 매수해 보유**하고 다시 관측했다.

미국 정규장 **09:53~10:02(한국 22:53~23:02)**에 1분 간격으로 10회, 같은 **0.01주**의 Backpack 매도 RFQ와 Jupiter V2·Raydium·Meteora 매도 견적을 조회했다. **10회 모두 RFQ 수신·취소에 성공했고, 관측용 매도 체결은 없었다.** 종료 시 SPCX 잔고는 **0.010093주**였다.

| 참고 모델 | 실제 Backpack RFQ보다 높은 정도: 평균 | 차이 범위 |
| --- | ---: | ---: |
| 미국 시장 최근가 | **+15.13 bps** | +6.49~+31.53 bps |
| 최근가에서 15 bps 차감 | **+0.11 bps** | −8.52~+16.48 bps |

보수 모델은 평균 차이가 작았지만 **10회 중 4회는 실제 매도 RFQ보다 높았다.** 평균에서 높은 값과 낮은 값이 상쇄된 것이며, 평균 절대 차이는 4.68 bps였다. “보수”라는 이름만으로 실제 매도가의 하한을 보장할 수 없었다.

같은 수량의 매도 견적은 Jupiter V2 통합이 Backpack보다 10회 모두 높았다. Raydium·Meteora는 각각 7회 높았다. 다만 **양쪽 매도가의 비교는 차익거래 수익이 아니다.** 매수 비용·전송 비용·이동 중 가격 변화는 별도로 계산해야 한다. V2 통합은 지갑 잔고 검사와 분리한 가격 조회로 요청했으므로, 즉시 실행 가능한 지갑 주문으로도 단정하지 않는다. [10회 관측의 방법·통계·원본](rfq-paired-observation-2026-09-11.md)

## 4. 기존 가격 수집과 백테스트는 어떻게 해석하나

9월 9일까지의 기존 집계에서는 4종의 **1주 비교 2,395개, 10주 비교 377개**가 비용 반영 수익률 **0.2%**를 넘지 못했다. 그러나 일부 평일 자체 호가가 시장 가격에서 크게 떨어져 있었다. 따라서 이 결과를 실제 브로커 가격에서도 기회가 없었다는 결론으로 사용하지 않는다. 반복 기록 역시 독립된 거래 건수가 아니다.

SPCX 과거 가격 **13,142개 구간**에 브로커 스프레드 30 bps 등 비용을 가정한 백테스트에서는 0.2% 이상 신호가 DEX→Backpack **145개(1.10%)**, 반대 방향 **42개(0.32%)**였다. 이는 과거 종가로 계산한 시나리오이며, 당시 거래 가능한 수량이나 실제 RFQ를 재현한 결과가 아니다. 5분 뒤 매도 계산도 작성했지만 개별 신호의 실현 수익으로 보지 않는다.

기존 집계는 **2026-09-09 15:35:55.790 UTC까지**의 표본을 유지했다. 이번 소액 실행과 10회 견적 비교는 별도 표본이며 합산하지 않는다. 과거 수치는 이번 보고서 개편에서 재계산하지 않았다. [가격 로그](../data/gaps.jsonl), [SPCX 백테스트](../data/backtest.SPCX.US.external.csv), [비용 가정별 비교](../data/backtest.sensitivity.csv)

## 5. 현재 성과와 남은 과제

**완료한 것은 가격 수집·비교 도구, SPCX 소액 경로 실행, 실제 RFQ 반복 비교다.** 견적·RFQ 처리 관련 테스트 10개도 통과했다. 참고 가격, 실제 수신 견적, 거래 후 정산가를 구분해야 한다는 점을 실험으로 확인했다.

아직 검증하지 않은 것은 **신호에 따라 진입한 거래의 반복 수익성, 1주·10주 실제 RFQ 비교, 다른 종목·시간대에서의 재현성**이다. 약 93초와 100초의 입금 관측으로 평균 처리 시간을 확정할 수 없고, 가격이 가깝다는 사실로 온체인·오프체인 장부의 갱신 속도가 같다고 말할 수도 없다. 지속 모니터의 현재 가동 상태는 이번 보고서 갱신에서 확인하지 않았다.

다음 단계는 같은 수량의 실제 견적 비교를 다른 시간대에 확장하고, 참고 모델의 오차를 확인하는 것이다. 규모를 늘리거나 추가 체결을 할 때는 목적과 예산을 먼저 정한다. 화면 개발과 실시간 로그의 이동 지연 반영 평가도 남아 있다.

아티클에는 **“전환 경로가 열려 있어도 가격 확인과 거래에 필요한 조건까지 사라지는 것은 아니다”**라는 발견을 연결한다. 다른 플랫폼의 가입·계정 연결·전환 후 거래 절차는 문서로 비교하되, 이번 프로젝트가 플랫폼 전체의 우열을 증명한 것은 아니다.
